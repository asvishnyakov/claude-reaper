# Probe results and the decisions they support

Every result here except P3b was observed on **Claude Code 2.1.296** on GitHub-hosted runners (`ubuntu-latest`: Linux 6.17; `macos-latest`: macOS 26.6.2, arm64; `windows-latest`: Windows Server 2025, build 26100), by [`probes/probe.py`](../../probes/probe.py) in workflow run 38324636651 (commit `010d64c`). Raw output: [Linux](linux.md), [macOS](macos.md), [Windows](windows.md). An earlier run (38324245155) gave the same answers, except that its Windows "other processes on its console" count was wrong (the helper counted itself); only the later run's figures are used. P3b was observed on **Claude Code 2.1.310** on the same runner labels, in workflow run 40354834423 (commit `7ce8806`).

The next plan (macOS and Windows `process` and `stop`, `daemon`, `install` and `uninstall`, release) is written from this table.

Later local checks on 2.1.310 (exit code per stop signal, how VS Code and terminal sessions take a stop, entrypoints) are in [stop-signal-local.md](stop-signal-local.md). They led to stopping with `SIGINT` instead of `SIGTERM` and selecting sessions by entrypoint (spec amendment of 2026-10-25); P3b confirms `SIGINT` in CI.

## Limits

- **Two versions.** Everything above except P3b was seen on Claude Code 2.1.296; P3b on 2.1.310, the version the probe and integration workflows now pin. `procStartFt` is absent in both, so nothing is known about how a version that records it behaves. A `procStart` that cannot be compared stays `process identity unverified` and is skipped.
- **P3b and unsent text.** A terminal session whose prompt showed typed, unsent text also exited with code 0 on `SIGINT`, so `--entrypoint cli` stops such a session too. Whether that text survives, for example after `claude --resume`, was not checked.
- **P5 imitates the extension's launch.** A small Node script spawns Claude Code with piped stdio and `windowsHide: true`, with the flags copied from a live VS Code session on the developer machine and the entrypoint label set by environment variable. It is not the extension itself.
- **P6 on Windows used `/run`.** A real logon cannot be triggered in CI, so `schtasks /run` stood in for the at-logon trigger. Neither service manager was observed starting a task at a real login.
- **P6 and the runner accounts.** All sessions ran as the runner's own user. Behaviour for a restricted user was not tested.
- **Nothing shared a console.** In every Windows launch, no other process was attached to the session's console, so the spec's accepted consequence (Ctrl+C also reaches a shell that launched Claude Code) was not exercised.
- **macOS `lstart` has one-second resolution.** A recycled PID started in the same second as the recorded process would pass the check. Linux uses clock ticks.
- **P7 was read from the probe, not from a service.** The environment was read by the probe process, not from a launchd or Task Scheduler context, which is how a daemon will run. Windows reads the live environment block while Linux reads the initial environment. `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` was not tested. The API names in the table are what `psutil` uses on each system; they were not observed directly.
- **The sessions' environment.** Only `CLAUDE*` and `ANTHROPIC*` variables were removed, so sessions also saw `CI`, `GITHUB_*` and `RUNNER_*`. The runner accounts are administrators, so on Windows the sessions ran elevated; a difference in elevation between reaper and session was not tested.
- **macOS `lstart` day padding.** Only a two-digit day was observed. `ps` pads days 1 to 9 with a second space, which was never compared with `procStart`.
- **Not probed:** a `CLAUDE_CONFIG_DIR` set only in a settings file, a session in a process group with Ctrl+C disabled (`CREATE_NEW_PROCESS_GROUP`), and Linux service management.

## Safe branches where a probe could not answer

- Identity not comparable on an OS or version: skip the session, `process identity unverified`.
- `AttachConsole` fails: skip the session, `no console to deliver Ctrl+C`.
- The environment of another process cannot be read: use `~/.claude`, the reaper's own environment and `--config-dir`.
